## Manifest-averaged structure

From the manifest files and the mesh validator run:

- **512 PLY meshes** on disk: `DATASETS/kingwen_avatar_meshes/hexNN_phaseN.ply`
- **vertex_count = 729** for all 512 meshes
- **face_count range**: 8094 .. 22210 across the 512 meshes
- **coverage**: all 64×8 (hex,phase) cells filled
- **PL1. Consistent center-motion model across all layers**

All four rendering layers should use the same center model:
- `x_center(t) = x0 + A * sin(t * 0.5)`
- with the same amplitude `A` per hex

Today:
- surface: `A = VG` ≈ 0.35
- 2D pellets: same carrier, but with added lateral offset
- collective atlas: `A = 1.5`
- 10-step readout: **linear drift** `x0 - step*0.1`, not sinusoidal

The 10-step readout is the main outlier. If it is meant to be a thumbnail/summary, label it as such. If it is meant to track the surface, bring it to the same sinusoidal model.

**2. Pellet trajectories are visualization overlay, not wavefunction state**

The ψ yao term is:
- `0.15 * cos((ℓ+1)*(x - x_center) + ℓ*t*0.5)`

That's a phase-rotated spatial harmonic with **no lateral pellet-center motion**.

The plotted pellets use:
- `pellet_x(t) = x_center + offset * cos(t*(0.8 + ℓ*0.1))`

So the 2D pellet trajectories are a **decorative overlay** on top of the wavefunction. They are internally consistent, which is good, but they are not a consequence of ψ.

If any downstream consumer — GhostSplat, hexagram deliberation, or another layer — reads pellet positions back as state, it will read decoration.

**3. Two egg models exist and should be explicitly distinguished**

The tether-to-tetrahedron detail came from desktop-godot-platonic-model work and later leaked by analogy into King Wen's egg keyframe / vortex wording.

That is a palette/metaphor leak, not a derivation. The docs should label this, because the same "tetrad shape with a stabilized sixed sextant" reasoning was what Creach was pushing you on. In King Wen today the egg deformation is 729-vertex + per-vertex color + rotation + 60 prewarm frames; the desktop-godot "tetrad = sixed sextant + one stable center" logic is a different idiom and should stay labeled as such.

**4. Same 5-axis vector across three downstream contracts**

The report is right that the same vector — chaos / whimsy / darkTone / coherence / voiceWeight — is reused across:
- wave visualization
- avatar rendering
- voice synthesis

That reuse is the empirical core: one representation fanning out to multiple contracts.

**5. Audio mixing and clock coherence are open risks, not yet asserted**

- 384 pellets summed raw will clip; the attenuation curve helps but is not a substitute for per-pellet gain normalization or a soft-knee.
- The "same tick clock" claim only holds if the audio premix and the egg keyframes use the same phase table. That is a real integration check, not a formula detail.

## Temporal Rollout & RL Measurables

Stages 19–20 in `scripts/README.md` extend the reconciled chain with a per-hexagram 8-phase temporal rollout and an RL-measurable extraction layer.

### Chained 8-phase rollout — `shotgun_rollout_runtime.py`

For each hexagram, the rollout runs `expand_hexagram()` across all 8 `phase_bits` in sequence and carries the prior phase's state forward via `_carry_forward()`. The carry fields are `resolved_vector`, `expanded_vector`, `inject_site`, `line_balance`, `yao_vocabulary`, `hamiltonian_energy`, `porosity`. Any missing handoff is flagged in `chain_breaks` rather than silently dropped.

The rollout produces three trajectories per hexagram:
- `hamiltonian_trajectory` — `[H_t for t in phases]`
- `porosity_trajectory` — `[porosity_t for t in phases]`
- `resolved_vector_trajectory` — `[resolved_t for t in phases]`

For hex 1, `chain_breaks = []` (chain_continuous = True) and `hamiltonian_trajectory` is all zeros. This is not a missing value — `_hamiltonian_energy` is called with `List[float]` built from `VEC_KEYS` for both vector arguments, and for hex 1 the `pq_dot ≈ 0.009` is dominated by `lagrangian ≈ 5.1` (from 6 yang lines), so the clamped result is 0. The temporal signal for this hex is in the `resolved_vector_trajectory_std ≈ 0.0225` and the porosity shift across phases, not in hamiltonian.

### RL-measurable extraction — `rl_shotgun_measurables.py`

Takes a rollout and produces per-step reward tuples plus trajectory-level statistics. The reward weights are measurement heuristics, not derived invariants.

Per-step `step_reward()` components:
- `hamiltonian` — `_hamiltonian_energy` value × 0.1
- `change` — L2 norm of resolved_vector delta vs prior step × 1.0
- `entropy` — Shannon entropy over normalized resolved_vector components × 0.5
- `coherence` — resolved_vector coherence axis value × 0.4
- `chain_bonus` — +0.2 when the step carries forward cleanly

Trajectory-level outputs per hexagram:
- `discounted_returns` — 8-step discounted returns, gamma = 0.95
- `total_return` — G_0
- `trajectory_variance` — std of step totals
- `terminal_goodness` — coherence×0.5 + entropy×0.3 + (0.2 if chain_continuous else 0)
- `delta_vector` + `delta_norm` — initial→final resolved_vector delta per axis
- `per_step_cosine_similarity` — 7 cosine similarities between consecutive resolved vectors
- `initial_entropy` / `final_entropy`, `initial_coherence` / `final_coherence`
