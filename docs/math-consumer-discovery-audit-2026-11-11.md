## 3. Consumer Extraction Algorithm

### 3.1 Current Algorithm

The manifest generator `scripts/build_datasets_manifest.py` creates entries with a default empty array:

```python
# Simplified from manifest generator
entry = {
    "dataset_id": ...,
    "relative_path": ...,
    "category": ...,
    "purpose": ...,
    "producer": ...,
    "consumers": [],  # <-- Default empty, never populated
    "schema": ...,
    "version": ...,
    "frozen": ...,
    "regeneration_policy": ...,
    "sha256": ...,
    "size_bytes": ...,
    "created_at": ...,
    "updated_at": ...,
}
```

**No consumer discovery logic is implemented.** The `consumers` field is hardcoded to empty.

### 3.2 What Would Discovery Need To Do?

For each manifest entry, consumer discovery would need to:

1. Scan the repository for imports of the dataset (static analysis)
2. Scan for configuration files referencing the dataset (dynamic loading)
3. Scan for documentation references
4. Cross-repository reference lookup
5. Differentiate between:
   - Documentation references (informational only)
   - Static code references (verified links)
   - Runtime dependencies (verified imports)

### 3.3 Current Implementation Gap

The current manifest generator does not:
- Scan source files for dataset imports
- Scan configuration files for dataset references
- Scan cross-repository references
- Track consumer attribution
